## Transport model and deterministic reference inventory

The teaching scenario uses six exact 15-byte P02 frames, a 200 ms period, 20 ms path delay,
1000 kb/s application serialization, loss index 3, a controlled 1000 ms TCP RTO, and an 800 ms
application deadline. The transparent standards boundary is consistent with TCP's reliable ordered
byte-stream service and UDP's delivery-without-reliability model; the lesson does not claim a full
TCP implementation or UDP application retry policy. See [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html),
[RFC 768](https://www.rfc-editor.org/rfc/rfc768.html), and
[RFC 6298](https://www.rfc-editor.org/rfc/rfc6298.html).

Baseline reference facts:

- P02 serialization is `8(15)/1000 = 0.120 ms`; no-loss service is `20.12 ms`.
- Send times are `[0 200 400 600 800 1000] ms`.
- UDP application delivery is `[20.12 220.12 NaN 620.12 820.12 1020.12] ms`.
- TCP modeled range arrival is `[20.12 220.12 1420.12 620.12 820.12 1020.12] ms`.
- TCP contiguous application delivery is
  `[20.12 220.12 1420.12 1420.12 1420.12 1420.12] ms`.
- TCP application ages are `[20.12 20.12 1020.12 820.12 620.12 420.12] ms`; head-of-line
  waits are `[0 0 0 800 600 400] ms`.
- TCP delivers `6/6` eventually and `4/6` on time; UDP delivers `5/6`, all five on time.
- The displayed TCP outcome assumes a sender window sufficient for all modeled ranges and receiver
  retention of out-of-order bytes. Baseline retains three modeled ranges, or 45 P02 application
  bytes. A modeled record-range attempt is not a TCP segment count.

Independent sweeps and limits:

- periods `[100 200 400] ms` produce TCP on-time counts `[3 4 5]`, UDP counts `[5 5 5]`, and
  maximum TCP head-of-line waits `[900 800 600] ms`;
- RTOs `[1000 1250 1500] ms` produce TCP on-time counts `[4 3 2]`, UDP counts `[5 5 5]`, and
  maximum TCP ages `[1020.12 1270.12 1520.12] ms`;
- no loss makes the TCP and UDP delivery timelines equal with all six on time;
- final-record loss recovers TCP record 6 at `2020.12 ms`, leaves one UDP gap, and causes no later
  range to wait;
- deadline equality at `20.12 ms` is on time, including at the allowed `1e6 ms` record period;
- a coincident recovery/next-range edge at large values produces zero artificial head-of-line wait;
- the model is capped at 64 records, 65 modeled TCP range attempts, 64 UDP datagram attempts,
  63 retained ranges, and 945 retained P02 application bytes.

The broken boundary fixture uses the exact P02 baseline frame twice:

`[126 0 11 42 18 52 255 106 255 206 0 50 0 150 135]`.

Two application writes of `[15 15]` bytes may appear as TCP read chunks `[9 21]`. The naive
one-read parser recovers zero. The bounded parser retains 9 bytes after the first read, then checks
sync, declared length, the 135-byte P02 frame policy, and checksum to recover two 15-byte frames
with zero remainder. A two-byte partial header waits; bad sync rejects before length; schema-valid
payload length 133 rejects the 131-byte payload policy before checksum; corruption rejects checksum;
a fresh valid parse recovers; and a third valid frame stops at the global two-frame cap with 15
stream bytes unconsumed. Parser policy is at most two frames, 135 bytes per frame, and 270 input
bytes; the fixed fixtures never allocate from their declared length.

## Residual risks

- No MATLAB or Octave executable was installed, so MATLAB parsing/execution, `run_checks.m`, figure
  rendering, UI callbacks, and MATLAB numerical fidelity remain unvalidated at runtime.
- Public helper syntax establishes only an R2019b lower bound; no MATLAB release-compatibility
  execution was available, so support for any specific release remains unvalidated.
- Python independently recomputes the timelines and parser states, but that is not MATLAB runtime or
  numerical-fidelity evidence.
- The transport model assumes an established TCP connection, one first-attempt loss, one successful
  timeout recovery, a sufficient sender window, and receiver retention of later ranges. It omits
  acknowledgements, fast retransmit, SACK, adaptive RTO/backoff, congestion/flow-control dynamics,
  finite socket buffers, segmentation/coalescing, reordering, duplication, connection failure, and
  UDP application retries.
- Record-range and datagram attempts are pedagogical bookkeeping, not packet, segment, or operating-
  system syscall counts. The application serialization term omits transport/IP/link overhead.
- The P02 parser expects alignment at the first candidate sync byte and rejects rather than
  resynchronizing. It does not implement escaping, streaming timeout, or authentication; P02's
  additive checksum remains intentionally weak.
- A deterministic selected loss is not a measured loss distribution or network prediction.
- After the compatibility-claim repair and public CLI behavioral test, the independent system-risk
  review found no remaining material static defect; human learner efficacy and teach-back quality
  have not been assessed.
