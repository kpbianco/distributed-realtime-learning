## Deterministic model and independent arithmetic

One sender emits versions `1:6` at `[0 10 20 30 40 50] ms`. The transparent governing equation is

`t_arrive(k) = t_send(k) + s*d(k)`

for delay vector `d=[20 5 35 5 25 0] ms`. Arrival events sort by `(arrival time, sequence)` so lower
sequence is the explicit exact-tie rule. A strict receiver delivers only `nextExpected`, holds
higher successors in a finite buffer, accepts an expected message at the exact gap deadline, and
fails closed after deadline or capacity failure. Each message assigns its sequence as state version,
making out-of-order state regression directly visible.

### Baseline

| Observable | Exact deterministic value |
| --- | --- |
| Inputs | scale `1`; capacity `2 messages`; timeout `100 ms`; message 3 available; strict ordering enabled |
| Send times | `[0 10 20 30 40 50] ms` |
| Arrival times by sequence | `[20 15 55 35 65 50] ms` |
| Raw arrival order | `[2 1 4 6 3 5]`; four pairwise inversions |
| Strict delivery | `[1 2 3 4 5 6]` at `[20 20 55 55 65 65] ms` |
| Buffer occupancy after arrivals | `[1 0 1 2 1 0] messages`; high-water `2 messages` |
| Hold by sequence | `[0 5 0 20 0 15] ms`; total `40 message-ms`; maximum `20 ms` |
| Applied state | trace `[0 1 2 3 4 5 6]`; zero regressions; final/latest version `6` |

The Python oracle independently constructs and sorts events, counts every inverted pair, simulates
the expected-sequence buffer, and recomputes delivery/holding/failure/state outputs. It does not read
MATLAB output values or execute the MATLAB implementation.
