## Protocol and deterministic reference inventory

The transparent teaching frame is:

`0x7E sync | uint16 big-endian declared payload bytes | type | uint16 sequence | int16 samples | checksum`.

It assumes the receiver is already aligned at the first sync byte. Payload `0x7E` escaping and
arbitrary stream resynchronization are intentionally not modeled and are recorded as residual risk.

Baseline `model(4,1000,0)` reference facts:

- samples: `[-150 -50 50 150]`;
- payload: `[42 18 52 255 106 255 206 0 50 0 150]`;
- frame: `[126 0 11 42 18 52 255 106 255 206 0 50 0 150 135]`;
- 11 payload bytes, 15 frame bytes, 120 wire bits, 0.120 ms at 1000 kb/s;
- checksum 135 and post-sync residue zero modulo 256;
- decoded type 42, sequence `0x1234`, and samples exactly match the inputs.

Independent sweeps and limits:

- sample counts `[0 1 4 16]` produce frame bytes `[7 9 15 39]` and times
  `[0.056 0.072 0.120 0.312]` ms at 1000 kb/s;
- rates `[125 1000 10000]` kb/s produce `[0.960 0.120 0.012]` ms while frame size
  and efficiency stay fixed;
- zero samples produce 3 payload bytes, 7 frame bytes, and checksum 141;
- 64 samples produce the maximum 131 payload bytes, 135 frame bytes, 1080 bits,
  1.080 ms at 1000 kb/s, and checksum 63;
- `+2` declares a valid 13-byte payload but supplies a 15-byte frame where 17 bytes are expected:
  2 bytes are missing, checksum evaluation is premature, and bounded timeout is required;
- `+3` produces an impossible even payload declaration and rejects immediately as invalid schema;
- `-2` is schema-valid but leaves two extra bytes and rejects;
- declarations above 131 payload bytes reject immediately without waiting, checksum evaluation, or
  allocation.
