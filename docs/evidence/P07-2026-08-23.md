## Governing numerical contract

Use `theta = follower clock - leader clock`. `T1` is modeled leader Sync transmit, `T2` follower
receive, `T3` follower Delay_Req transmit, and `T4` leader receive. With forward delay `d_f`,
reverse delay `d_r`, follower turnaround `g`, and exchange origin `T0`, the ideal reference-plane
timestamps are

```text
T1 = T0
T2 = T0 + d_f + theta
T3 = T0 + d_f + g + theta
T4 = T0 + d_f + g + d_r
```

For captured timestamp error `e_i = captured T_i - ideal T_i`:

```text
theta_hat = ((T2+e2 - T1-e1) + (T3+e3 - T4-e4))/2
          = theta + (d_f-d_r)/2 + (e2-e1+e3-e4)/2

delay_hat = (T4+e4 - T1-e1) - (T3+e3 - T2-e2)
          = d_f+d_r + e4-e1-e3+e2
```

The `g` term cancels from both estimates. The model uses a fixed eight-exchange host-latency
fixture and fixed raw hardware placement offsets `[-20 +80 -20 +20] ns`. Full correction applies
the opposite signs after raw timestamps are rounded to the nearest configured tick. Exact
half-tick ties round away from zero. These constants and the quantizer are teaching fixtures, not
device specifications.

Baseline `(T0, theta, d_f, d_r, g, host scale, tick, calibration) =
(100000, 120, 800, 800, 4000, 1, 8, 1)`:

- first ideal reference-plane timestamp vector: `[100000 100920 104920 105600] ns`;
- software offset estimates: `[170 320 120 270 220 70 420 120] ns`;
- hardware offset estimates: `[118 118 122 118 122 122 118 122] ns`;
- software offset mean/range/maximum absolute error: `213.75/350/300 ns`;
- hardware offset mean/range/maximum absolute error: `120/4/2 ns`;
- true network round trip: `1600 ns`;
- software round-trip estimates: `[4500 4800 4800 5100 5000 5100 5200 4800] ns`;
- hardware round-trip estimates: `[1596 1596 1604 1596 1604 1604 1596 1604] ns`;
- hardware per-stamp quantization residual bound: `4 ns`; and
- all ideal, software-placement, hardware-calibration, and hardware-quantization identities: zero
  residual in the retained reference fixture.

A fractional-input regression uses `(T0, theta, d_f, d_r, g, host scale, tick, calibration) =
(100.5, -0.5, 1.25, 1.25, 10.5, 0, 0.5, 1)`. Software remains exact at `-0.5 ns`
offset and `2.5 ns` round trip. Rounding places both follower events `0.25 ns` later, so hardware
reports `-0.25 ns` offset and `2.5 ns` round trip. The independent Python oracle and retained
MATLAB assertion agree on this intentional quantized result.

The signed half-tick regression sets all event times to zero before pipeline placement with an
`8 ns` tick. First-exchange raw values `[-20 80 -20 20] ns` quantize to
`[-24 80 -24 24] ns`, yielding residuals `[-4 0 -4 4] ns`. It exercises both negative and positive
ties in the model's accepted signed time domain.

The host scale sweep `[0 1 2]` produces software offset ranges `[0 350 700] ns`, maximum absolute
offset errors `[0 300 600] ns`, and maximum absolute round-trip errors `[0 3600 7200] ns`.
Hardware offset range/error stays `4/2 ns`, and hardware maximum round-trip error stays `4 ns`.

The hardware tick sweep `[1 8 64] ns` produces offset ranges `[0 4 32] ns`, maximum offset errors
`[0 2 22] ns`, round-trip ranges `[0 8 64] ns`, and maximum round-trip errors `[0 4 52] ns`.
The software trace is unchanged. Independent arithmetic verifies the general teaching bounds:
each raw rounded stamp contributes at most `q/2`, the four-stamp offset combination at most `q`,
and round trip at most `2q`.

The deliberately broken case uses a `1 ns` tick and calibration fraction zero. All eight hardware
offset estimates are exactly `150 ns` for true `120 ns`, while every round-trip estimate is
`1740 ns` for true `1600 ns`. Both traces have zero spread. Applying twice the correction yields
`90 ns` and `1460 ns`, flipping both bias signs. This demonstrates that repeatability does not
prove timestamps share the intended calibrated reference plane.

The inherited P06 limit remains explicit: at a fine tick with full calibration, `1200/400 ns`
forward/reverse delay produces `520 ns` estimated offset for true `120 ns`; swapping directions
produces `-280 ns`. Both retain `1600 ns` round trip.

## Model basis and inference boundary

The placement direction is grounded in primary implementation documentation, while all numerical
fixtures are local engineering choices:

- Linux kernel timestamping documentation distinguishes software RX capture after driver handoff,
  software TX capture before the interface, and PHY capture closer to the wire; it also warns
  against late software fallback because it creates unexpected deltas:
  <https://docs.kernel.org/networking/timestamping.html>.
- linuxptp configuration documentation defines `egressLatency` as added to hardware TX timestamps
  and `ingressLatency` as subtracted from hardware RX timestamps:
  <https://www.linuxptp.org/documentation/default/>.
- MathWorks documents the one-argument nearest-integer rule used here, including away-from-zero
  handling for exact ties:
  <https://www.mathworks.com/help/matlab/ref/double.round.html>.
- The NXP TJA1103A data sheet documents device-specific ingress/egress pipeline compensation,
  supporting the need for calibration without supplying evidence for this synthetic fixture:
  <https://community.nxp.com/pwmxy87654/attachments/pwmxy87654/other/31576/1/TJA1103a.pdf>.

Inference: these sources support the capture-plane and correction-sign abstraction. They do not
validate the chosen latency arrays, tick behavior, MATLAB implementation, or any physical device.
